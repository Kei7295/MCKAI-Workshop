一、项目概述

1.1 项目背景

MCKAI 模组工坊是一款基于 Android 原生开发的 AI 辅助 Minecraft 模组开发工具。它将三大知名开源项目的核心理念融合为一：

参考项目Stars核心特性MCKAI 集成情况
RikkaHub6.7K多 Provider LLM 客户端、消息分支、Markdown 渲染、MCP 协议多 Provider 支持、消息树结构、富文本渲染
Operit6.6KAI Agent 平台、40+ 工具、工作流引擎、JS 扩展桥工具注册中心、25+ 内置工具、Agent 三模式路由
ModCrafting15Minecraft 模组 AI 生成、三模式路由、Vibecoding Agent模组生成引擎、Plan/Execute 双阶段、5 平台脚手架

1.2 设计理念

  • AI 驱动：自然语言描述即可生成完整可编译的模组项目
  • 多模型支持：接入 OpenAI、Gemini、Claude、DeepSeek、通义千问等主流模型
  • 工具调用：LLM 可调用文件操作、网络请求、计算、Minecraft 数据查询等工具
  • 平台全覆盖：Fabric、Forge、NeoForge、Bedrock 基岩版、网易版
  • 原生体验：Kotlin + Compose，Material 3 设计语言，暗色/亮色主题

二、核心功能详解

2.1 多模型 AI 对话系统

支持的 Provider 类型

支持 6 种 Provider 类型：
├── OpenAI          (GPT-4.1, GPT-4o, o3, o4-mini)
├── Gemini          (Gemini 2.5 Pro/Flash)
├── Claude          (Claude Opus 4, Sonnet 4)
├── OpenRouter      (200+ 模型统一网关)
├── Ollama 本地     (Llama 3.1, Qwen 2.5, DeepSeek-R1)
└── 自定义兼容      (任何 OpenAI 兼容 API)

对话功能亮点

  • 流式输出：基于 SSE (Server-Sent Events) 的实时流式响应
  • 工具调用：Function Calling，LLM 可自动调用外部工具
  • 推理过程展示：显示模型的 Reasoning/Thinking 过程
  • Provider/模型热切换：对话中可随时切换模型
  • API Key 池轮转：支持多个 API Key 自动轮换
  • 自定义 HTTP 头：支持自定义请求头
  • 连接测试：一键测试 Provider 连接状态
  • 多模态支持：文本 + 图片 + 文件内容

2.3 Agent 三模式引擎

架构设计

用户输入 → 模式分类器 → 路由到对应处理器
                        ├── Chat 模式 → 普通对话（无工具调用）
                        ├── Plan 模式 → 结构化规划（最多 15 轮只读分析）
                        └── Execute 模式 → 逐步执行 + 工具调用（最多 40 轮）

模式分类规则

模式触发关键词适用场景
Chat默认，无特殊关键词日常问答、概念解释、头脑风暴
Plan"分析"、"规划"、"计划"、"设计"、"架构"、"怎么做"需求分析、架构设计、方案制定
Execute"生成"、"写"、"创建"、"实现"、"开发"、"编码"、"build"实际编码、文件生成、问题修复

Execute 模式工具循环

循环（最多 40 轮）：
  1. 发送消息给 LLM
  2. 收集响应（文本 + 工具调用）
  3. 如果有工具调用：
     a. 执行工具
     b. 将结果作为 tool message 加入历史
     c. 继续下一轮
  4. 如果无工具调用或达到上限：
     a. 保存助手消息
     b. 结束

3.3 LLM 客户端

LlmClient 是核心的 HTTP 客户端，支持 6 种 Provider 类型的流式通信：

请求构建流程

buildRequest(provider, systemPrompt, messages, tools)
  ├── OpenAI/OpenRouter/Ollama/Custom
  │   ├── URL: {baseUrl}/chat/completions
  │   ├── Auth: Bearer {apiKey}
  │   └── Body: OpenAiRequest (model, messages, tools, stream=true)
  ├── Gemini
  │   ├── URL: {baseUrl}/v1beta/models/{model}:streamGenerateContent?alt=sse
  │   ├── Auth: x-goog-api-key
  │   └── Body: GeminiRequest (contents, systemInstruction, tools)
  └── Claude
      ├── URL: {baseUrl}/v1/messages
      ├── Auth: x-api-key + anthropic-version: 2023-06-01
      └── Body: ClaudeRequest (model, messages, tools, stream=true)

响应解析

使用 SseParser 解析 SSE 流，自动检测 SSE 和 NDJSON 格式：

  • SSE 模式：标准 Server-Sent Events，以 data: 前缀标识
  • NDJSON 模式：每行一个 JSON 对象
  • 空行分隔：空行表示事件块结束
  • [DONE]：OpenAI 协议结束标记

六、Agent 引擎详解

6.1 模式分类算法

fun classifyMode(input: String): AgentMode {
    // 1. 检查显式命令
    if (input.startsWith("/chat")) return CHAT
    if (input.startsWith("/plan")) return PLAN
    if (input.startsWith("/exec")) return EXECUTE

    // 2. 关键词匹配
    val execKeywords = ["生成", "写", "创建", "实现", "开发", "编码"]
    if (execKeywords.any { input.contains(it) }) return EXECUTE

    val planKeywords = ["分析", "规划", "计划", "设计", "架构"]
    if (planKeywords.any { input.contains(it) }) return PLAN

    // 3. 默认 Chat
    return CHAT
}

## 目标

## 步骤
1. 第一步...
2. 第二步...

## 注意事项

6.3 Execute 模式工具循环

最多 40 轮工具调用循环：

  1. 发送消息给 LLM（含系统提示 + 历史 + 用户输入）
  2. LLM 返回文本 + tool_calls
  3. 执行所有工具调用
  4. 将工具结果作为 tool message 加入历史
  5. 继续下一轮，直到无工具调用或达到上限

七、模组工坊详解

7.1 生成流程详细说明

Step 1: 选择平台

  • 5 个平台卡片，点击选择
  • 显示平台名称、默认 MC 版本、描述
  • 选择后自动设置 MC 版本

Step 2: 描述模组

  • 模组名称：必填，英文名称
  • Mod ID：可选，默认从名称生成
  • MC 版本：默认平台版本，可修改
  • 描述：模组的功能描述
  • 功能需求：详细的功能列表
  • AI 模型：选择用于生成的模型

Step 3: AI 生成

  • Agent 引擎自动运行
  • 实时显示生成进度和日志
  • 显示已生成文件数量
  • 可随时取消

Step 4: 查看结果

  • 显示生成的文件列表
  • 成功/失败状态
  • 可导出为 ZIP 项目
  • 可保存到项目库
  • 可重新生成

十一、开发指南

11.1 构建项目

# 前提条件
# - JDK 17
# - Android SDK (platforms;android-35, build-tools;35.0.0)
# - Gradle 8.11.1

# 构建 Debug APK
gradle :app:assembleDebug

# 输出路径
app/build/outputs/apk/debug/app-debug.apk

11.2 添加新的 Provider

  1. 在 ProviderType.kt 中添加枚举值
  2. 在 LlmClient.kt 的 buildRequest() 中添加请求构建逻辑
  3. 在 LlmClient.kt 的 parsePayload() 中添加响应解析逻辑
  4. 在 ProviderPresets.builtIn() 中添加预设配置

11.3 添加新的工具

  1. 在 domain/tools/ 下创建或编辑工具文件
  2. 使用 r.register(ToolMetadata(...), handler = { ... }) 注册
  3. 工具会自动被 ToolRegistry.buildDefault() 加载
  4. LLM 会通过 getToolsForLlm() 获取工具定义

11.4 数据库迁移

当前使用 fallbackToDestructiveMigration()，生产环境应编写 Migration：

val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE conversations ADD COLUMN assistantId INTEGER")
    }
}
// 在 AppDatabase.build() 中添加
.addMigrations(MIGRATION_1_2)

11.5 代码规范

  • 使用 Kotlin 官方代码风格
  • ViewModel 使用 AndroidViewModel + Factory
  • 状态管理使用 StateFlow + MutableStateFlow
  • 协程使用 viewModelScope.launch
  • Room 使用 Flow 观察数据变化
  • UI 组件使用 Compose Material 3
  • 不添加不必要的注释
